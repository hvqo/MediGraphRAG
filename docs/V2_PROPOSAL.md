## 创意与交互

### 1. 左边读教材，右边问答和出题

导入后直接打开 PDF 页面或正文。点击一句话的引用，跳到对应页并高亮支持句；
选中一段资料可发起解释、生成考点或出题。表格单元格、标题路径与正文分别保留。

新增片段字段：页码、标题路径、版面坐标、解析器版本和原文版本。
继续保留轻量文本解析，Docling 作为可选解析器，先用同一批教材对照测试，再决定是否默认启用。

验收：引用能定位原页面；表格不会被拼成含义错误的一行；解析失败可回看和重新处理。

### 2. 可审核的医学关系图谱

把现在的“概念共现”与“资料明确陈述的医学关系”分开。
每条候选关系附原句、出处、适用条件、版本和审核状态；审核通过后才能参与图谱事实检索。
例如疾病、症状、检查和药物是实体类型，具体医学关系必须由资料支持，不能仅因同段出现就成立。

点击一条检索路径，既能看关系，也能看路径中每条边的原文。保留共现图作为浏览层。

验收：无出处的关系不能标记为已确认；删除或更换来源时，相应关系自动失效；
分别比较关键词、向量、文本与图谱融合模式的结果，证明图谱带来何种收益。

### 3. 出题蓝图与考点覆盖矩阵

先设置章节、知识点、题型、认知层次和数量，再生成试卷。
矩阵展示各知识点覆盖率，避免一批题目反复考同一个事实。保存题目与考点、资料、
模板版本之间的对应关系。单题生成与整卷组题共用同一个题目对象。

验收：生成前能预览出题分布；生成后能发现重复考点和空缺；题目难度标记与真实答题难度分开。

### 4. 为每个干扰项提供审题意见

审题不只返回 True/False，而是逐项给出：正确或错误的依据、可能歧义、题干是否泄漏答案、
解析是否超出资料。给教师展示引用完整性、答案一致性、唯一性检查等独立维度，
不将它们混成一个冒充医学准确率的总分。

允许生成模型与审题模型独立配置；同一模型复核仍明确标注为同一模型。
保存失败候选用于问题分析，但不把失败候选放进正式题库。

验收：多答案单选题、引文不存在、解析超出资料等固定反例被拦截；教师能编辑和说明驳回原因。

### 5. 指南版本变化提醒

资料注明年份、版本、发布来源和适用范围。检索遇到不同版本的不同表述时并列展示；
资料更新后找出受影响的关系、答案和题目，将其标为待复核。
系统提供变化线索，具体医学判断仍由专业人员确认。

验收：能列出某资料版本所影响的题目；不会静默地用新资料替换旧题的历史依据。

### 6. 病例题组与错题到知识点的回路

同一病例可以覆盖判断、检查解释等多个教学考点；题组中的已知事实保持一致。
学生端记录作答后，将错题映射到知识点，推荐相应原文与新的练习题。
有足够真实作答数据后再统计实际难度、区分度和干扰项选择情况，
不能仅靠模型写下“困难”就认为已完成难度校准。

验收：病例题组情境一致；学习记录能回到知识点和原文；出题教师与学生作答界面分开。

### 7. 效果评测和运行回放

固定一组由专业人员确认的中文医学资料与问题，分别记录检索命中、引用匹配、
人工判定的依据支持度、答案正确性、审题通过率、耗时和调用量。
保存模型、提示词、资料与索引版本，使一次失败可复现。
MedRAG 的方法可借鉴，但其语料与评测成绩不能直接代表本项目的中文效果。

## 目标工程结构

当前已整理为：

```text
backend/app/       Python 后端与领域模块
frontend/src/      Vue 单文件组件、JavaScript 与 CSS
legacy/            历史 Python 工具和实验源码
tests/             回归测试
scripts/           启动、验证与迁移工具
docs/              计划、进度、调研与迁移说明
pyproject.toml     Python 包元数据和命令行入口
```

下一轮按功能拆分后端内部的资料、证据、图谱、评测和试题模块；路由只负责输入输出。
前端增加 Vue Router、Pinia，并逐模块迁到 TypeScript，提供类型检查和可分享页面地址。
数据迁移引入版本管理；需要多人协作时再引入 PostgreSQL、用户和角色权限。
维持单体服务与独立任务执行边界，部署能力随真实需求增加。

| 阶段 | 改动 | 验收成果 |

| P0 已执行 | Notebook 源码迁出、前后端分区、命令行、包元数据与 CI | 零 Notebook；原代码可追溯；原功能回归通过 |

| P3 教学特色 | 出题蓝图、干扰项审查、生成/审题模型分工 | 可按章节组织一套可审核的题 |
