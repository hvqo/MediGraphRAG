## 推荐使用顺序

1. **医学资料库 → 资料阅读器**：导入原文件；轻量解析默认可用，Docling 未安装时禁用。
   填写发布来源、版本、年份、章节、适用范围。PDF 引用定位对应页，并在文字层匹配引句；
   无法匹配时明确提示核对正文。选中文字可发起当前片段问答或出题。
2. **关系与出处**：从片段提取候选，或手工录入主体、关系、客体、逐字引句与条件。
   原句存在只证明引用匹配，医学关系是否成立需要人工审核。通过后才用于两跳路径与融合检索。
   共现图仍在“知识图谱”，明确区分共现与医学关系。
3. **模型与设置**：本地/云端生成保持原有切换；审题可选相同模型、另一台本地模型或云端模型。
   同一种来源共用地址/密钥，可以分别指定模型名称。分别检查生成和审题连接。
4. **蓝图与病例**：设置章节、知识点、认知层次、题型、预期难度和数量，保存后检查出题分布。
   每行最多10题、每份蓝图最多20行且不超过100题，任务排队执行。覆盖矩阵统计已生成、已审、空缺与重复题干。
   病例材料附来源并单独人工审核，同一题组共享冻结的病例情境；可导出整卷中依据有效的已审核题。
5. **题库与审核**：核对每个干扰项的自动审查理由与引文，查看是否同一模型复核。
   自动检查通过仍进入待审；教师编辑会清空旧自动审查记录并重新待审。导出保留考点及病例情境。
6. **练习与复习**：用本机学习档案区分记录。练习先隐藏答案，提交后返回解析和出处；错题映射到知识点和原文，
   推荐同考点另一题。教师统计区分预期难度和真实首次作答，样本不足显示空值。
7. **效果评测**：固定问题、预期片段和人工参考答案，人工确认后比较关键词、向量、审核关系与融合模式。
   记录每种模式的召回、MRR、耗时与实际使用方式。向量不可用标为“未运行”。
   系统不自动生成或评判医学答案；人工答案评价需附实际答案及判定依据。
8. **运行与回放**：查看模型、模板版本、提示词、原文集合指纹、耗时和服务返回的 token 数。
   缺少 token 数时显示未返回。失败候选保留供排查。按原配置回放会重新调用服务，
   不写正式题库；资料变化则阻止回放。服务端权重变化或随机性可能导致结果不同。

## 资料升级与失效处理

- 在新资料的阅读器选择旧版，先看文字差异、受影响题目、关系和问答调用记录，再确认版本关联。
- 历史文件保留供追溯，旧版退出默认检索；涉及题目退回待审，失效关系不再用于事实检索。
- 删除、重新解析或重新分块造成引文失效时，题目和关系会标记待复核，并记入题目操作记录。
- 资料集合指纹包含文字和出处信息，不仅比较片段 ID；重新解析后即便位置相同也能检测文字变化。
- 索引过期需要重建；旧题不能在没有有效引用时通过审核或导出。

## 可复现检查

从仓库根目录使用现有环境，不需要再次更换 Python：

```powershell
& ..\.venv\Scripts\python.exe -m unittest discover -s tests -v
& ..\.venv\Scripts\ruff.exe check backend tests scripts main.py
& ..\.venv\Scripts\python.exe scripts/check_repository.py
& ..\.venv\Scripts\python.exe scripts/benchmark_retrieval.py
cd frontend
npm ci
npm run format:check
npm run typecheck
npm run build
```

已装 Playwright 和 Chrome 时，从根目录运行 `scripts/check_v2_ui.py`，自动启动临时应用和
明确标注的软件模型 HTTP 桩，验证全流程后清理临时数据，不改生产题库/设置。
`scripts/check_reader_ui.py` 与 `scripts/check_ui.py` 需要先启动本机应用，结束时清理测试资料。
`scripts/check_local_model.py` 会实际调用本机 Ollama；它与固定中文验收集都不构成医学评测。

本机现有 qwen2.5 权重位于 `E:\manifests` / `E:\blobs` 的 Ollama 模型目录，
本轮启动服务时设置了进程环境 `OLLAMA_MODELS=E:\`，未重复下载模型、未改系统永久环境变量。
以后自行重启 Ollama 时需使用对应模型目录，或在设置中填写该服务可见的准确模型名称。
