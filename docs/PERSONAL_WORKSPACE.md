# 从用户要做的事开始 · 0.6.0

目标是少操作：让用户说出目的，系统决定解析、检索与归档步骤。没有给普通用户增加检索方式、OCR开关、向量建库或图数据库选项。

## 已实现的场景

| 用户场景 | 操作 | 系统行为 |
|---|---|---|
| 学生查知识 | 输入问题并发送 | 语义检索优先；关系/比较意图按需补充审核路径；返回回答和原句 |
| 教师准备练习 | 选一批文件，点击生成练习题，或输入数量要求 | 同页显示题目、解析、逐项审查与依据，核对后即可加入练习 |
| 课堂截图 | 粘贴截图，直接问或要求提炼 | 自动识别、保留原图、加入自己的资料库 |
| 新教材/指南 | 拖入PDF、Word和图片 | 原生文字先读；文字页CPU OCR；图示/不确定页用本地视觉模型；优先完成当前任务 |
| 暂时只收集资料 | 上传后不写要求，发送 | 默认提炼示例知识点；后台自动索引，并提示可继续做什么 |
| 继续处理一批资料 | 直接追问或点结果旁的操作 | 沿用本批文件范围；说“全部资料”可回到整个库 |
| 网页关闭/服务重启 | 重新打开最近任务 | 从持久记录恢复任务和结果；出题中断明确标记，可重试 |

## 保存与调度

1. 上传API先将原文件分批写入当前档案的staging，再返回任务ID。批次最多100份，每份25MB；PDF每份最多500页。
2. 每份文件独立解析，失败文件保留原件与原因，不阻止其余文件。已有同内容文件直接复用解析结果；同进程重复图像复用识别结果。
3. 前台请求优先：提问、提炼或出题。完成后立即显示结果，无需等待整个资料库建立向量或图关联。
4. 向量每批16片段持久化并让出队列；新前台任务优先于下一批后台工作。一页/一次正在执行的模型调用不会强行中断。
5. 关系按原文片段逐步补充，记录“原文提及”、引句、出处与状态。医学关系候选须人工审核后才用于事实深查。
6. 后台失败显示真实状态，仍可用关键词查已保存文字。不会把缺模型或向量失败写成“索引完成”。

批量保存没有逐页生成知识点：当前示例提炼最多取12份资料的代表片段、最多8个考点；完整正文仍存储并可检索。请求默认范围为空时取最近100份有效资料，问答可检索整个当前档案。整章覆盖、完整知识点清单和长教材整卷需要后续分层提炼/蓝图，而不能靠一次长提示词冒充完成。

## 个人档案是什么

- 使用随机身份Cookie（HttpOnly、SameSite=Strict）识别本机浏览器，服务器仅保存身份摘要。
- `.runtime/libraries/<ID>`内每档案拥有独立SQLite、uploads、staging、FAISS索引、设置、题库与任务。跨档案文档/任务ID不能读取。
- 第一个档案复制旧SQLite、文件和设置，原库保持保留。后续浏览器身份创建空库；不会把别人的数据自动导入新库。
- 这是本机隐式档案，不是用户名密码登录或公网权限系统；清Cookie会创建新档案。备份保留整个`.runtime`；账号恢复、跨设备同步和细化共享尚未实现。

## 为什么采用两级识别

真实视觉基线中，三份干净打印医学资料用了431.73秒。相同图片嵌在Word里还重复识别，浪费时间。

现在优先原生正文；可选RapidOCR在CPU识别明显文字页。白底、行结构、识别分数和非文字笔画覆盖规则用于决定是否接受；这些是启发式，不是临床置信度。图示/表格问题或不确定页面转视觉模型，原图始终可回看。识别结果只进入文本向量索引，尚未实现独立图片向量或视觉语义召回评测。

有明显图示时仍需视觉模型，不能把它的图中文字当完整医学图理解。自然照片、手写、复杂版式与医学影像质量尚无代表性验收。已知打印摘要的字符错误率与耗时见[实测报告](MEDICAL_BENCHMARK.md)。

## 继续演进

下一步优先考虑资料上传即生成“这批资料能做什么”的个性化建议、按章节增量提炼、长教材后台覆盖矩阵、按难度自动组卷、错题触发带出处讲解。建议动作应直接复用已上传资料和最近上下文，避免新增配置页面。医学实体消歧、否定/条件关系及多跳推理需要独立医学标注和专家验收后再扩大自动化。
